#  Настройка окружения

Наиболее удобно будет проходить курс на компьютере с _Unix_ окружением.

Под _Windows_ для удобства компиляции и запуска лучше использовать 
_WSL_ (_Windows Subsystem for Linux_).

Рекомендуется использовать _Ubuntu_ версии **24.04**.

## Установка зависимостей

Проект имеет следующие зависимости:

- `git` - контроль версий Git
- `gcc` - компилятор (версия >= 14)
- `clang` - компилятор (версия >= 20)
- `cmake` - система сборки (версия >= 3.14)
- `GoogleTest` - фреймворк для тестирования

Установка:

```sh 
    sudo apt update && sudo apt upgrade
    sudo apt install g++-14 clang-20 cmake gdb git
    sudo apt install libgtest-dev libgmock-dev
    sudo apt install clang-format-20 clang-tidy-20
```

После установки следует проверить успешность установки компонент и версий:

```sh
    g++ --version
    clang++ --version
    cmake --version
    git --version
```

Если версии не совпали с требуемыми, возможно у вас несколько версий программ.
Решите данную проблему самостоятельно. Можно перенастроить версию по умолчанию 
или просто явно указать версию при запуске: `clang++-20`, `g++-14`

## Настройка SSH-ключа для GitHub

Чтобы отправлять решения в свой репозиторий без ввода пароля, нужен SSH-ключ.
Если ключ уже добавлен в **_GitHub_**, этот шаг можно пропустить.

```sh
ssh-keygen -t ed25519 -C "<email как при регистрации>"   # на все вопросы можно нажать Enter
cat ~/.ssh/id_ed25519.pub                                # скопируйте выведенную строку
```

Затем на **GitHub**: ЛКМ по аватару -> **Settings** -> **SSH and GPG keys** -> **New SSH key**.  
Вставьте скопированную строку и сохраните. 

Проверить подключение:

```sh
ssh -T git@github.com
```
- в ответ должно прийти приветствие с вашим логином.

## Настройка локального репозитория

Решения задач должны храниться в приватном репозитории, чтобы их не видели другие 
участники курса. Поэтому не делайте **Fork** публичного репозитория: форк публичного 
репозитория на _GitHub_ всегда публичный, и закрыть его нельзя.

Вместо этого создаем собственный приватный репозиторий и загружаем в него копию курса.

1. Зайдите на страницу [GitHub с репозиторием курса](https://github.com/psds-cpp/psds-cpp-2026) 
   и поставьте ему звёздочку (опционально) — кнопка `⭐Star` в правом верхнем углу.
   Так всегда будем знать сколько человек на курсе.  
  
2. Создайте приватный репозиторий на **_GitHub_**.

- В верхнем углу `+` -> `New repository` 
- Заполнить имя репозитория `psds-cpp-2026`
- Видимость установить приватной `Private`
- `README.md`, `.gitignore`, `license` — не добавляйте, репозиторий должен быть пустым
- Нажмите внизу кнопку `Create repository`.  
  
3. Используя терминал склонируйте курс и загрузите в свой приватный репозиторий:

```sh
# Скачиваем публичный репозиторий курса
git clone https://github.com/psds-cpp/psds-cpp-2026.git

# Переходим в директорию склонированного репозитория
cd psds-cpp-2026

# Настраиваем пользователя
git config --local user.name "<логин как при регистрации>"
git config --local user.email "<email как при регистрации>"

# Настраиваем, чтобы при git pull объединять изменения слиянием (merge)
git config --local pull.rebase false

# Публичный репозиторий курса называем upstream — из него будем получать обновления
git remote rename origin upstream

# Свой, ранее созданный в GitHub, приватный репозиторий называем origin
# В него будем отправлять решения
git remote add origin git@github.com:<ваш логин>/psds-cpp-2026.git

# Загружаем курс в свой приватный репозиторий
git push -u origin main
```

4. Проверить настройку можно командой `git remote -v`. Должно получиться:

```text
origin    git@github.com:<ваш логин>/psds-cpp-2026.git (fetch)
origin    git@github.com:<ваш логин>/psds-cpp-2026.git (push)
upstream  https://github.com/psds-cpp/psds-cpp-2026.git (fetch)
upstream  https://github.com/psds-cpp/psds-cpp-2026.git (push)
```
- `origin` — ваш приватный репозиторий: сюда отправляются решения (`git push`).
- `upstream` — репозиторий курса: отсюда приходят новые задачи (`git pull upstream main)`.

5. Добавьте преподавателя в коллабораторы

- Преподавателя необходимо добавить в коллабораторы, чтобы он мог смотреть за выполнением
задач в вашем приватном репозитории.
- В своём репозитории откройте **Settings** -> **Collaborators** -> **Add people**.
- Добавьте преподавателя: [18thday](https://github.com/18thday).

6. Проверьте, что включены **GitHub Actions**

- Откройте в своём репозитории вкладку **Actions**.
- Там должны быть видны _workflow_: `Testing Tasks` и `Testing Tasks Week ##`. 
- Если **GitHub** предлагает включить **Actions**, нажмите кнопку включения.

## Получение обновлений

В течении всего курса публичный репозиторий будет постепенно наполняться.
Будут появляться еженедельные задачи, конспект лекций, код примеров.
Также возможно будут обновляться тесты и условия существующих задач.
Перед началом выполнения заданий и после лекций следует подтягивать обновления.
Подтянуть изменения из публичного репозитория можно с помощью выполнения
команды из корня репозитория:

```sh
git pull upstream main     # получить обновления курса
git push                   # сохранить их в своём удаленном репозитории
````

Если при `git pull` откроется текстовый редактор с сообщением
`Merge branch 'main' of ...` — просто сохраните и закройте его.

Если `git pull` сообщает о конфликте, значит обновился файл, который вы тоже меняли.
Разрешите конфликт в указанных файлах, затем выполните `git add <файл>` и `git commit`.

## Работа на другом компьютере

Свой репозиторий можно склонировать на любой компьютер, но удалённый репозиторий 
`upstream` при этом нужно добавить заново:

```sh
git clone git@github.com:<ваш логин>/psds-cpp-2026.git
cd psds-cpp-2026
git remote add upstream https://github.com/psds-cpp/psds-cpp-2026.git
```
